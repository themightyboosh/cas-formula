# Data Flow: How Your Firestore Data Powers the App

## ✅ YES - This is the ACTUAL data used in the frontend!

Here's exactly how it works:

## The Complete Flow

```
User Completes Assessment
         ↓
Frontend calls: personalizeApproach Cloud Function
         ↓
Cloud Function (functions/src/index.ts:234)
    ├─ Fetches from: db.collection('affectCombinations').doc(casElement)
    ├─ Gets from Firestore:
    │   ├─ feeling (line 249)
    │   ├─ approach (line 250) ← Base therapeutic text
    │   ├─ weather (line 251)
    │   └─ spotify_seed (line 252)
    ↓
Cloud Function personalizes with Gemini AI
    ├─ Takes: approach text from Firestore
    ├─ Personalizes: With user's subject and pronouns
    └─ Returns: Modified approach text
    ↓
Returns to Frontend (line 360-367):
    ├─ casElement (e.g., "CuJoSt")
    ├─ feeling ← DIRECT from Firestore
    ├─ approach ← Personalized by AI
    ├─ weather ← Personalized version
    ├─ musicGenre ← Extracted from spotify_seed
    ├─ spotifyQuery ← Generated by AI
    └─ spotifySeed ← DIRECT from Firestore
    ↓
Frontend displays results (index.html:1334-1348)
    ├─ Shows feeling text
    ├─ Shows personalized approach
    ├─ Shows weather description
    └─ Fetches 3 Spotify tracks using spotifySeed
```

## The 504 Combinations You See in Admin

**Location:** Firestore → `affectCombinations` collection

**Fields Used:**
- `Affect1`, `Affect2`, `Affect3` → Used to generate CAS code (e.g., CuJoSt)
- `feeling` → Displayed directly on results page
- `approach` → Base text that gets personalized by AI
- `weather` → Personalized with user's subject
- `spotify_seed` → Used for Spotify Recommendations API
- `spotify_prompt` → (Not currently used, backup)
- `valence_raw` → (Not used in frontend)
- `valence_category` → (Used for admin filtering only)

## Example: User sorts affects as [Curiosity, Joy, Surprise]

1. **Frontend generates CAS code:**
   - Curiosity → Cu
   - Joy → Jo
   - Surprise → St
   - Result: "CuJoSt"

2. **Cloud Function fetches from Firestore:**
   ```javascript
   db.collection('affectCombinations').doc('CuJoSt').get()
   ```

3. **Gets this exact data you see in admin:**
   ```json
   {
     "Affect1": "Curiosity",
     "Affect2": "Joy",
     "Affect3": "Surprise",
     "feeling": "exploratory radiant layered with startled depth",
     "approach": "Mirror your Curiosity about {{subject}}. Let Joy help you celebrate...",
     "weather": "Bright, shifting skies with variable winds...",
     "spotify_seed": "seed_genres=synth-pop,indie-pop&target_valence=0.85&target_energy=0.72"
   }
   ```

4. **AI personalizes for user's subject:**
   - Input: "my job"
   - Replaces: `{{subject}}` → "your job"
   - Adjusts pronouns, grammar, etc.

5. **Frontend displays:**
   - Feeling: "exploratory radiant layered with startled depth"
   - Approach: Personalized version with "your job"
   - Weather: Personalized weather description
   - Spotify: 3 tracks from Recommendations API using seed_genres=synth-pop,indie-pop

## What Gets Modified vs. What Stays Direct

**Direct from Firestore (unchanged):**
- ✅ `feeling` text
- ✅ `spotify_seed` parameters
- ✅ CAS element code

**Modified by AI:**
- 🤖 `approach` text (personalized with subject/pronouns)
- 🤖 `weather` text (personalized with subject)
- 🤖 `spotifyQuery` (generated for fallback, not used if spotifySeed exists)
